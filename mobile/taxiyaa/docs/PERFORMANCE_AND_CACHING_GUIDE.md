# In-App Caching & Performance Architecture Guide — AdminAstrogaon

This document outlines the caching, network optimization, and performance architecture for the `adminastrogaon` Flutter application communicating with the Laravel backend (`astrogaon.com`).

---

## 🖼️ 1. Image Caching & Memory Management

### A. Dual-Tier Image Caching (`cached_network_image`)
All remote image URLs (service images, user avatars, temple banners, blog post covers) use two-tier caching:
1. **Disk Cache**: Stores downloaded images in the device's local cache directory (`getTemporaryDirectory()`), enabling instant offline rendering across app launches.
2. **RAM Memory Cache**: Retains decoded image pixels in active memory during navigation.

```dart
CachedNetworkImage(
  imageUrl: item.url,
  memCacheWidth: 400, // Downscale decoded pixels in RAM to prevent high GPU/memory usage
  placeholder: (context, url) => const AutoSkeleton(...),
  errorWidget: (context, url, error) => const Icon(Icons.broken_image_outlined),
)
```

### B. Image Memory Downscaling (`memCacheWidth` / `memCacheHeight`)
- High-resolution camera uploads (4000×3000px) consume 45+ MB of RAM when uncompressed in Flutter engine.
- Always specify `memCacheWidth: 400` or `memCacheHeight: 300` when loading images into list tiles or card containers to cap decoded memory footprint at ~0.5 MB per image.

### C. Backend Thumbnail Presets (Laravel MediaConversions)
- Mobile clients MUST request pre-generated WebP image thumbnails (`ThumbnailPreset`) generated by Laravel MediaLibrary (e.g., `Card Thumbnail` 400×300, `Avatar` 150×150).
- Downloads 15–30 KB WebP thumbnails over cellular data instead of 3–5 MB original uploads.

## 🌐 2. API Response Caching Techniques

### A. Riverpod In-Memory Caching (Stale-While-Revalidate / SWR)
Prevent duplicate network calls when switching between tabs or returning to previously visited screens:

```dart
@riverpod
Future<Map<String, dynamic>> storageDashboard(Ref ref) async {
  // Retain cached API data in memory for 5 minutes
  final link = ref.keepAlive();
  final timer = Timer(const Duration(minutes: 5), () => link.close());
  ref.onDispose(() => timer.cancel());

  return ref.watch(storageRepositoryProvider).fetchStorageIndex();
}
```

### B. Local Persistent Cache (Hive / LocalStorage)
For offline support and instant 0ms initial render:
1. **App Launch**: Read and display last cached JSON payload instantly from local disk.
2. **Background Fetch**: Request fresh data from `/api/v1/*` endpoint.
3. **Silent Update**: Overwrite disk cache and notify Riverpod providers when fresh data arrives.

```dart
Future<Map<String, dynamic>> getCachedOrFetch(String key, Future<Map<String, dynamic>> Function() fetcher) async {
  final box = Hive.box('api_cache');
  final cached = box.get(key);

  // Return cached payload immediately if available
  if (cached != null) {
    fetcher().then((fresh) => box.put(key, fresh));
    return Map<String, dynamic>.from(cached);
  }

  final fresh = await fetcher();
  await box.put(key, fresh);
  return fresh;
}
```

### C. HTTP ETag & 304 Not Modified Headers
- The Laravel API sends an `ETag` header with every GET response.
- `ApiClient` includes `If-None-Match: "etag-hash"` on subsequent requests.
- When the database record has not changed, Laravel returns **HTTP 304 Not Modified** with zero body bytes, saving cellular data bandwidth.

## ⚡ 3. Performance Guidelines for Production Build

1. **Server-Side Pagination**:
   - All list endpoints (`/admin/users`, `/admin/bookings`, `/admin/storage`, `/admin/blog`) must use Laravel `LengthAwarePaginator` (20 items per page).
   - Never stream unpaginated 1,000+ item payloads to mobile devices.
2. **Input Debouncing**:
   - Debounce search and filter text input changes by 300ms–500ms using a `Timer` to avoid firing rapid API requests on every keystroke.
3. **Repaint Boundaries & Fixed Item Extents**:
   - Wrap heavy custom lists or shimmer skeletons in `RepaintBoundary` widgets.
   - Use `itemExtent` or `prototypeItem` in `ListView.builder()` where possible for 60/120fps smooth scrolling.
4. **Const Constructors**:
   - Enforce `const` on all static widget subtrees so the Flutter framework skips re-building unchanged elements.
5. **No Fake Data Fallbacks**:
   - Never catch network errors silently to inject mock lists. Show real API errors with retry actions as defined in `GEMINI.md`.
